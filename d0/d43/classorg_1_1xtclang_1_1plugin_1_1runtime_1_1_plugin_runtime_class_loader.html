Detailed Description

Child-first loader for runtime implementation classes that must resolve against the selected XDK runtime rather than the already-loaded plugin classloader.

Only the small implementation package is child-first. Everything else stays parent-first on purpose so the outer plugin API surface, Gradle APIs, and request DTO types are shared rather than duplicated across classloaders.
