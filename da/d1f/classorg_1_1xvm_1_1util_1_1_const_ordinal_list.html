Detailed Description

An immutable List of Integer implementation that stores a compressed form of an int[] or a List<Integer> in a byte array.

This is not intended to be a general purpose compressor; it is designed for a small set of use cases, such as compressing a list of enumeration ordinals.

See the notes on ConstBitSet for some background on the high-level design goals for the data structure.

Several forms of compression are used: Repetition of the same value can be represented as a "repeating node"; The most common value can be omitted altogether, since absence of data implies that value; When values need to be stored, only the necessary significant number of bits need be used.

The format is a sequence of variable-length nodes, of several different forms. Each form of node is composed of:

  • An implicit byte id for the node (a byte id is the index into a conceptual byte array that backs the bit set);
  • A skip byte id (encoded as a relative value to this node's implicit byte id) for the node that can be skipped forward to in the bit set, or zero to indicate that no skip forward option is available from this node;
  • The number of bytes to skip forward (this field only exists if the skip byte id is non-zero);
  • A next byte id (encoded as a relative value to this node's implicit byte id) for the node that immediately follows the current node, or zero to indicate that this is the last node in the bit set (i.e. EOF).

The run-length node form adds: The run length (encoded as a negative value to indicate RLE); The run value.

The array node form adds: The number of values; The bytes necessary to hold those values (typically fewer bytes than the number of values, since only the minimum necessary LSBs for each value are stored). The header is composed of compressed integers: The array length; The default element value; The number of bits per element (for non-RLE nodes); The id of the first node.

The array node form adds: The number of values; The bytes necessary to hold those values (typically fewer bytes than the number of values, since only the minimum necessary LSBs for each value are stored).

Considered and rejected: The values in the list may be representable with smaller values by replacing frequently encountered large values with smaller identity values that represent the original values, with the array of original values indexed by the identity values (and likely stored at the end of the data structure). This capability was omitted because it is compositional with this data structure, so could be implemented separately.
